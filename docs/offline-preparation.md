# 로봇 연결 전 검증

이 단계는 ROS2·로봇·그리퍼 없이 Python 가짜 백엔드로 분기와 명령 순서를 검사합니다.
물리 시뮬레이션이나 실제 제품 파지 성공률 검증은 아닙니다.

## 실행

저장소 루트의 `warehouse_motion/` 디렉터리에서 가상환경으로 실행합니다. 모의 코드는 소스에서만 실행합니다. Python 3.10 이상이며 ROS2 대상 환경은 별도로 확인합니다.

```bash
cd warehouse_motion
python -m pip install -e ".[test]"
python -m pytest test -q
python -m offline_picking.mock_demo --products snack_box pet_bottle can wet_tissue doll
python -m offline_picking.mock_scenario
python -m offline_picking.mock_scenario --case unconfirmed-place
```

`mock_demo`는 가짜 백엔드를 직접 생성하며 실물 드라이버를 import하지 않습니다.
가상 파지 프로필과 실제 이동 백엔드를 섞으면 첫 동작 전 차단합니다.

`offline_picking.mock_scenario`는 박스 트리거·RFID·주문 조회·비전 검출을 가짜 데이터로 연결합니다.
정상 사례는 상품 3개 적치 확인 후 홈 복귀까지 실행합니다.
`--case`는 `normal`, `unknown-tag`, `missing-product`, `empty-grasp`, `unconfirmed-place`, `cancel`을 지원합니다.
정상 종료 코드는 0, 의도한 실패/취소 사례는 1입니다.
실제 RFID 서버나 주문/재고 DB에 접속하지 않습니다.

## 완료한 준비

- 높이·속도·가속도와 설정값의 NaN/무한대 차단.
- `taught: "false"` 같은 문자열을 실물 교시 승인으로 취급하지 않도록 수정.
- 상품 5종별 독립 파지 프로필 스키마와 합성 테스트값.
- 열림 확인 → 파지 → 안정화 확인 → 상승 → 유지 확인 → 이동·적치 → 열림 확인 → 퇴피.
- 빈손 파지, 예상 폭 밖 접촉, 과전류, 응답 시간 초과, 오래된/중복 피드백, 파지 유지 실패, 취소 처리.
- 실패 시 이동 정지 요청과 그리퍼 움직임 중단 요청. 자동 홈 복귀·자동 해제·자동 전류 증가는 하지 않음.
- 합성 주문 수량 반복, 슬롯 분리, 적치 확인 후 완료 수량 반영.
- 같은 실행기 인스턴스의 요청 중복 방지, 동시 실행 거부, 부분 완료·취소·상태 수신 실패 처리.

## 상품별 그리퍼 동작

`gripper_profiles.yaml`의 상품 키는 `products.yaml`과 같습니다.
그리퍼가 단단함을 직접 측정하는 방식이 아니라, 상품별 검증 프로필을 선택하는 방식입니다.

| 설정 | 역할 |
|---|---|
| open_width_mm | 상품에 접근하기 전 손가락 사이 폭 |
| target_width_mm | 닫힘 명령의 목표 폭. 정상 물체 접촉 폭보다 작게 설정 |
| min_width_mm / max_width_mm | 물체를 잡았을 때 허용할 실제 폭 범위 |
| close_speed_mm_s | 손가락 닫힘 속도 |
| current_limit_ma | 모터 전류 상한. N 단위 파지력이 아님 |
| contact_current_ma | 접촉 후보를 판단하는 전류 기준 |
| settle_s | 새 피드백에서 폭·전류 조건이 연속 유지되어야 하는 시간 |
| timeout_s | 파지/열림 상태 확인의 제한 시간 |

손가락을 상품보다 넓게 열고 접근한 뒤 목표 폭으로 닫습니다.
예상 폭 범위에서 손가락 이동이 멈추고 전류가 접촉 기준을 만족하는 상태가 안정적으로 유지돼야 다음 단계로 갑니다.
완전히 닫힌 빈손 상태, 폭 범위 밖 걸림, 과전류는 실패입니다.
들어 올린 뒤에도 폭과 전류를 다시 확인합니다. 실패했다고 더 세게 재시도하지 않습니다.

이 조건은 접촉과 파지 유지의 간접 판정입니다. 전류만으로 실제 파지력이나 상품 손상을 측정할 수 없습니다.
유연한 포장·인형은 변형 때문에 실물 허용 폭과 접촉 기준을 특히 주의해 조정해야 합니다.
해제 시에는 손가락 열림만 확인하므로, 물체가 실제로 박스에 떨어졌다는 확인은 별도 센서·비전 정책이 필요합니다.
모션 계층은 주문/재고 DB를 갱신하지 않습니다.

## 실물 연결 때만 채울 것

모든 `real` 프로필은 `calibrated: false`입니다. 지금 `mock`의 수치를 복사하면 안 됩니다.
실물에서는 정확한 RN/RN(A) 모델·펌웨어·전원·프로토콜, 엔코더→손가락 폭 변환,
전류 단위와 속도 제한, 상품 폭·재질·무게·패드 마찰을 확인한 뒤 프로필을 검증합니다.
실제 그리퍼 통신 어댑터와 ROS2 Action 서버는 아직 구현되지 않았습니다.
어댑터는 위치·전류·동작·오류·최근 수신 시각을 `GripFeedback`으로 제공하고 각 I/O 호출에 시간 제한을 둬야 합니다.
`halt()`는 무조건 토크를 끄거나 손가락을 열면 안 됩니다. 실제 장비의 유지·정지 동작을 확인해 구현합니다.

TCP·Tool·작업대 높이, 박스별 스캔/적치/접근/퇴피 위치와 경유점도 연결 후 측정합니다.
SafeMover는 도착 TCP 검사이며 경로와 링크·리더기·운반 물체 충돌을 검증하지 않습니다.

## 연결 전에 이어서 할 순서

1. [연결 초안](integration-contract.md)을 팀과 확인: 상품 ID, 박스/슬롯, Base 좌표·단위, 적치 확인 주체.
2. 별도 로컬 팀 코드에 추가한 단일 상품 REST API를 주문 단위 실행기로 연결. 박스별 빈 슬롯·점유·공간 부족 처리 추가.
3. RFID→박스→주문과 실제 비전 Base 좌표 입력을 연결. 적치 판정 주체는 합의 필요.
4. Ubuntu/ROS2에서 Action 인터페이스와 워커를 구현하고 빌드·취소·타임아웃·중복 요청 검사.
5. 실물 전환 전에 실행 이력 영속화, 재시작 후 상태 대조와 주문/재고 결과 중복 반영 방지 구현.

## 추후 고려사항

D455 깊이 기반 물체 폭 추정, 자동 그리퍼 열림 폭과 카메라 좌표 보정은 이번 단계에서 제외합니다.
현재 상품별 폭·전류 숫자는 가짜 백엔드의 분기 검사용입니다. 실제 측정값이나 비전 추정값이 아닙니다.

정확한 상품별 파지 폭·전류·속도, 교시 좌표와 충돌 검증은 이 오프라인 검사에서 확정할 수 없습니다.
